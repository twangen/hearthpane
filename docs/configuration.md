# Configuration reference

HearthPane uses the same nested shape in YAML and in its visual designer. Dashboard-wide fields live under **Dashboard settings**; selecting a widget opens one contextual editor with its data, display, position, and action fields. Design mode arranges widgets, while Preview mode renders the real card with actions disabled:

```yaml
type: custom:hearthpane-card
appearance: {}
background: {}
layout:
  format: vertical-2-1
  spacing: {}
  zones:
    middle-left:
      widgets: []
```

## Appearance

`fontFamily`, `fontColor`, `accentColor`, `textShadow`, `locale`, `timeZone`, `scale`, `railColor`, `glassColor`, and `scrimColor` are supported. All CSS custom properties generated by HearthPane use the `--hp-` prefix.

## Backgrounds

The default `picsum` source supplies a rotating set of free random 1920×1080 photos. `media` accepts a Home Assistant path such as `/local/backgrounds/photo.jpg` or an authenticated `media-source://` identifier. `url` accepts one image URL, and `images` accepts an explicit list. `opacity`, `rotationInterval`, `objectFit`, `position`, and `transitionSeconds` control presentation.

A legacy background that omits `source` but contains `config.entity` is normalized to the sensor source. An explicitly selected source always wins, which prevents the visual editor from snapping back to Sensor. `openweathermap`, `unsplash`, and `immich` display an editor warning and never make a network request.

## Layouts and zones

Formats are `3x3`, `vertical-2-1`, `vertical-1-2`, `horizontal-2-1`, and `horizontal-1-2`. Each active named zone has `widgets`, plus optional `align`, `justify`, `direction`, and `glass` settings. Widget IDs must be stable and unique.

## Widgets

- `clock` and `date`
- `current-weather` and static `forecast` rows; animation is limited to current conditions to reduce rendering work
- `agenda` and `month-calendar`
- `entity`
- `alerts`
- `action-bar`
- `separator`
- `ha-card`
- `transportation`

Clock and date widgets support `fontSize`, `fontWeight`, `fontStyle`, and `textAlign`. The visual designer presents font size as a numeric pixel selector, weights from Light through Bold, Normal or Italic style, and left, center, or right alignment. Existing CSS font sizes such as `9rem` remain supported in YAML and are converted to their numeric equivalent when opened in the designer.

The transportation widget reads an array from a Home Assistant entity attribute. `rowsAttribute` selects the array, and `fields.name`/`fields.time` map row values. It never calls an external transit provider.

## Actions

Action bar entries support `none`, `assist`, `navigate`, `url`, `more-info`, `toggle`, and `perform-action`. New actions default to `none`. For Assist, use `pipeline_id: preferred` and `start_listening: true` when the selected device can capture audio.

See [examples/classic.yaml](../examples/classic.yaml) for the full Classic preset.
